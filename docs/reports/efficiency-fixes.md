# 内存与效率优化记录

## B1

改动：SQLite 游标逐条解码并输出 JSON 数组，不再构造全部课程对象列表。
保留原子发布、历史归档及原有 UTF-8/缩进/换行格式。
验证：89 个测试通过，新增空数组/嵌套对象/Unicode 字节兼容和迭代中途异常保留旧文件测试；静态检查通过。

## B2

改动：快照以 64 KiB 块计算哈希、比较和复制；复制时复核哈希，源文件中途变化时不发布快照。
保留快照独立 inode、排他发布、损坏检测及临时文件清理。
验证：91 个测试通过，新增禁止 read_bytes 的跨块样本测试及复制期间源文件变化测试。
2,491 门实际数据导出与原 JSON 字节一致；流式导出与分块归档后的 Python 堆峰值已实测，明显低于此前约 10.54 MiB。

## B3

改动：SQLite 触发器跟踪课程结果版本，按输出路径持久化导出版本与哈希。
版本未变化时校验当前文件和快照，跳过课程解码、序列化、重写和重复归档；缺失快照可恢复。
手工编辑、缺失输出或数据变化会重新导出，损坏历史快照仍明确报错。
验证：95 个测试通过，覆盖跨进程重开复用、状态变化但结果不变、手工编辑、文件缺失、
直接 SQL 删除、结果更新和快照损坏；静态检查通过。

## B4

改动：每页建立 FieldIndex，一次扫描 label 后按名称查找字段；单字段辅助函数和既有导入入口保留。
遵守首个重复 label、大小写/冒号规范化及嵌套字段归属规则。
验证：96 个测试通过，新增索引仅扫描一次、重复查询及重复 label 兼容测试；官方课程与 A4 回归通过。

## B5

改动：单轮任务成员在 SQLite 临时队列中冻结，Python 每次最多读取 100 个 URL，
主流程不再构造全部待处理 URL 列表；保留显式列表兼容入口。
验证：98 个测试通过，覆盖处理期间状态变化、同轮不重试失败 URL、新入队任务留待下一轮、
limit/pending 优先、非法批量大小与中断后的游标释放。静态检查通过。

## B6

改动：CLI 仅在向终端输出时构造 JSON 字符串，文件输出直接使用原子 JSON writer。
验证：99 个测试通过，新增禁止多余 dumps 调用的文件输出测试；终端输出回归和静态检查通过。

## B7

改动：增加 status 索引，将 pending/failed 分阶段按 rowid 选择，避免带 OR/CASE 的全表扫描和排序。
保持 pending 优先、总 limit 和单轮冻结语义；已有数据库自动创建索引。
验证：100 个测试通过；对实际执行的待处理和失败队列 SQL 检查执行计划，确认使用 status 索引，
没有 SCAN courses 或临时排序；静态检查通过。

## B8

改动：提供可选 --commit-batch-size，默认 1 继续逐门提交。批量模式按指定大小提交，
正常结束提交尾批，Ctrl-C 尽力提交已完成尾批，其他致命错误回滚未提交批次。
验证：103 个测试通过，使用独立 SQLite 连接验证提交边界、尾批与错误回滚，
子进程强制退出验证未提交批次可恢复为 pending；非法参数及既有逐门提交回归通过。

## B9

改动：提供 --workers 1..16，默认 1；线程池最多保留 workers 个任务，抓取/解析并发、SQLite 单线程写入。
每个抓取线程复用独立 Session，全部共享线程安全的请求间隔及 Retry-After/退避冷却。
关闭时取消未执行任务，等待已开始任务释放资源；数据库检查点只记录已保存结果。
验证：107 个测试通过，覆盖真实线程重叠、并发上限、主线程写入、单页失败隔离、
独立 Session 与统一限速、资源释放、非法并发数及批量提交组合。静态检查通过。
