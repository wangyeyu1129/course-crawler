# T03：统一 Pydantic 课程模型与字段状态

## 问题与目标

原 12 字段字典将页面没有字段、字段为空、结构解析失败都表示为 null，
无法为后续资格判断提供可靠的数据质量依据。手写类型校验也没有验证来源状态与值是否矛盾。

本次以严格 Pydantic 模型统一课程契约，在新采集过程中保存来源证据，保留既有 CLI 和 JSON 投影。

## 实现与行为

| 改动 | 行为 |
| --- | --- |
| Course / CourseData | 统一模型、旧投影、严格类型、额外键禁止、必填内容及嵌套不可变状态 |
| FieldState / CourseFieldStates | 区分 present、empty、not_provided、parse_failed、unknown，拒绝矛盾状态或无诊断失败 |
| 旧数据桥接 | 旧 null 保留 unknown；明确空字符串标准化为 null 并记录 empty；读取不重写旧库 |
| DOM 观察 | 内容节点为空才记 empty；标签和已知语义容器均缺失才记 not_provided |
| 结构异常 | 重复容器、缺少自身内容节点、标签归属或语义容器不匹配、内容落在节点之外记 parse_failed |
| UTM 来源配置 | 标签与选择器集中在适配器 FieldSpec；domain 不依赖 DOM 或校区规则 |
| 解析接口 | parse_course_document 返回带状态模型；旧 parse_course_page 返回严格验证后的 12 字段字典 |
| 用例与存储 | 新成功 result 保存模型 JSON；解析失败保存可识别的字段诊断，单页失败继续处理后续课程 |
| 导出与缓存 | 逐条模型校验后导出旧投影，保留流式写出；格式版本 2 使旧缓存重新验证 |
| 依赖与指纹 | 固定 Pydantic 及传递依赖；模型状态定义变化进入 parser 指纹 |

可选字段解析失败的模型可用于诊断，但不能作为成功课程保存或通过常规导出发布。
必需 Description 缺失、为空或损坏时直接失败，同时保留观察到的状态。
刷新失败保留上次有效结果和其状态，本次失败原因单独保存在 error 中。

采用模型组合、边界校验及既有适配器/validator 端口；未引入新的服务、继承框架或全局状态。
模型内的校区、来源地址和 CSS 规则仍由适配器负责，避免把 UTM 规则写入共享领域模型。

## 兼容性

CLI 参数、退出行为和课程 JSON 的 12 字段结构保持。
新模型通过 from_legacy 接收旧记录，旧 validate_course 和 parser 字典接口继续工作。
直接使用原 TypedDict 构造方式的 Python 调用方需改为 Course.from_legacy；
应用层自定义 validator 返回值升级为 Pydantic Course，而非普通字典。
SQLite 没有新增列；新结果增加 payload schema_version 与 field_states，旧结果仍可读取。

## 限制

not_provided 表示当前适配规则下没有字段证据，不等于已经证明没有选课要求。
旧 JSON 投影不携带状态，不能用于还原来源证据。
旧 null 记录只有重新采集或从原始 HTML 重解析，才能获得可靠观察状态。
本次不新增关系表达式、corequisite、学分或学年字段，身份字段仍由校区适配器严格验证。
